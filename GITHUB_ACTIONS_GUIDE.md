# GitHub Actions Workflow Guide for Truth or Dare Deluxe

This guide explains how to use the GitHub Actions workflow to automatically build the Truth or Dare Deluxe app.

## Overview

The GitHub Actions workflow automates the following tasks:
1. Generates 1000 questions per category for Classic, Couples, and Party modes
2. Generates 100 questions per category for Drink mode
3. Builds the Android APK
4. Makes the APK available for download as an artifact

## Workflow File

The workflow is defined in `.github/workflows/android-build.yml` and includes the following steps:
- Checkout code
- Set up JDK 17
- Generate questions using the enhanced question generator
- Build the app with Gradle
- Upload the APK as an artifact

## How to Use the Workflow

### Automatic Triggers

The workflow runs automatically on:
- **Push to main branch**: When you push changes to the main branch
- **Pull requests to main branch**: When a pull request targeting the main branch is created or updated

### Manual Trigger

You can also manually trigger the workflow:

1. Go to your GitHub repository
2. Click on the "Actions" tab
3. Select "Android Build" from the list of workflows
4. Click "Run workflow" button
5. Select the branch you want to run the workflow on
6. Click "Run workflow" to start the build

### Accessing the APK

After the workflow completes successfully:

1. Go to the completed workflow run
2. Scroll down to the "Artifacts" section
3. Click on "truth-or-dare-deluxe" to download the APK
4. Install the APK on your Android device

## Customizing the Workflow

### Changing the Questions

To modify the questions generated by the workflow:

1. Edit the `enhanced_question_generator.kt` file
2. Commit and push your changes
3. The workflow will use your updated generator to create new questions

### Modifying the Build Process

To change how the app is built:

1. Edit the `.github/workflows/android-build.yml` file
2. Modify the build commands or add additional steps
3. Commit and push your changes

## Troubleshooting

### Common Issues

1. **Build Failures**
   - Check the workflow logs for specific error messages
   - Ensure all dependencies are correctly specified
   - Verify that the Kotlin version is compatible with the project

2. **Question Generation Failures**
   - Check for syntax errors in the `enhanced_question_generator.kt` file
   - Ensure the output directories exist and are writable
   - Verify that the JSON structure is valid

3. **APK Not Available**
   - Make sure the workflow completed successfully
   - Check that the artifact upload step completed without errors
   - Verify the path to the APK file in the workflow file

### Getting Help

If you encounter issues with the workflow:

1. Check the GitHub Actions documentation: https://docs.github.com/en/actions
2. Review the workflow run logs for specific error messages
3. Search for similar issues in the GitHub community forums

## Advanced Configuration

### Adding Custom Build Variants

To add custom build variants (e.g., release builds):

1. Edit the workflow file to include additional Gradle tasks
2. Add signing configuration for release builds
3. Update the artifact upload step to include the new APK files

### Scheduled Builds

To set up scheduled builds (e.g., nightly builds):

1. Add a `schedule` trigger to the workflow file:
   ```yaml
   on:
     schedule:
       - cron: '0 0 * * *'  # Runs at midnight UTC every day
   ```

2. Customize the cron expression as needed
